## Hypothesis and frozen representation

PR441's conservative exact-chip reference reaches its 10M-key threshold near
18–19M nodes and leaves 503/510 synthetic river observations missing at100M.
One opt-in `stack-buckets` schema tests whether replacing selected exact numerical
amounts with buckets reduces fragmentation and improves retained learning/support.
This is imperfect-recall abstraction, not an exact encoding or strength hypothesis.

The candidate retains the existing live-order K50/betting summary unchanged and
adds all fields below in button-relative physical-seat order:

- Exact player count, actor, blinds and every initial stack. The same independent
  uniform27tuple20/50/100BB chance law remains the checkpoint/export identity.
- Every seat's folded and zero-remaining-stack flags, including folded contributors.
- Ordered pair comparisons (<,=,>) for total contributions and current-street bets,
  preserving contribution-level ordering and equality rather than exact layer sizes.
- Original button-relative last aggressor for each street through the current one.
- Bucketed current pot in BB using the existing edges2/4/8/16/32/64/128.
- For each seat, remaining stack, current-street bet, total contribution and prior-
  street contribution, each relative to max(current pot,BB). Zero has its own tag;
  positive amounts use edges1/16,1/8,1/4,1/2,1,2,4,8,16 with integer comparisons.
- Actual call-is-all-in flag and the ordered production menu's labels, kinds and
  raise-is-all-in flags. Raise increments above the matched amount use the same
  amount buckets relative to max(pot after call,BB).

No raw numeric target is copied from another state. Rows store probabilities
under matching action labels; the host reconstructs each action's actual legal
raise-to amount from the current legal observation. Equal abstract action labels
can deliberately denote different legal numerical amounts. This declared loss
of precision must be reported; compatibility does not prove strategic equivalence.
No new menu, card abstraction, sampler/RNG, importance weighting or CFR arithmetic.
Old schema bytes, identities, consumers and defaults must remain unchanged.
